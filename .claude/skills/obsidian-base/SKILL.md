# Obsidian Bases — .base File Format

**TRIGGER when:** reading, writing, validating, or reasoning about any `.base` file in the vault; user asks about Obsidian Bases syntax, filters, views, or properties; any task that moves vault folders and requires updating `file.inFolder()` paths.
**SKIP:** general Obsidian markdown notes, frontmatter edits, or tasks unrelated to `.base` files.

---


Obsidian Bases (introduced in Obsidian 1.8+) uses plain YAML `.base` files to define structured views over note frontmatter properties. Files are human-editable and live anywhere in the vault.

## Top-level sections

A `.base` file has five optional top-level keys:

```yaml
filters:      # which notes to include
formulas:     # calculated virtual properties
properties:   # display-name overrides for columns
summaries:    # aggregations shown at column footoms
views:        # one or more table / card / list / map views
```

---

## filters

Filters narrow the set of notes shown. They can be defined globally (applies to all views) or per-view.

The `filters` value must be an object with exactly one of `and`, `or`, or `not` as its key. A bare list is not valid.

```yaml
filters:
  and:
    - file.inFolder("FolderName")        # notes inside a specific folder
    - status == "active"                 # frontmatter property comparison
    - date > date("2024-01-01")
```

Nesting:

```yaml
filters:
  and:
    - file.inFolder("E_Projekte")
    - or:
      - include == true
      - new == true
```

---

## views

Each entry in `views` defines one tab shown in the Bases UI.

```yaml
views:
  - type: table          # table | cards | list | map
    name: "My View"
    order:               # columns to show, in order
      - Akteur
      - Position
      - "Übergeordnete Akteure"   # quote names with special chars
    filters:             # view-local filters (narrowed further from global)
      - include == true
    groupBy:
      property: Status
    limit: 100
    summaries:
      Anzahl: Sum
```

The `order` list controls both **which columns are visible** and their **left-to-right sequence**. Properties not listed are hidden.

---

## properties

Use this section to override display names without affecting filter/formula logic:

```yaml
properties:
  A_Projektträger:
    displayName: "Projektträger"
  Q_Quellen_schriftlich:
    displayName: "Schriftliche Quellen"
```

---

## Full example — single-table base for one vault folder

```yaml
filters:
  - file.inFolder("E_A_Personen")
views:
  - type: table
    name: E_A_Personen
    order:
      - Akteur
      - Nachname
      - Vorname
      - Titel
      - Position
      - Anmerkung
      - "Übergeordnete Akteure"
      - Partei
```

---

## Property reference syntax

| Reference | Meaning |
|-----------|---------|
| `propertyName` | Frontmatter key (YAML key in the note) |
| `file.name` | Filename without extension |
| `file.path` | Vault-relative path |
| `file.mtime` | Last-modified date |
| `file.inFolder("X")` | Filter: note is inside folder X |
| `formula.myFormula` | Reference a formula defined in `formulas:` |

## Notes for this project

- Folder names used in `file.inFolder()` are the **sanitized folder names** from `folder_map` in `migrate.py` (e.g. `E_A_Kollektive_Akteure`, `w_Städte`).
- The `order` list should match the field list from `keep_schema.json` for that table, minus derived fields (`lookup`, `formula`, `rollup`, `count`).
- `.base` files are generated by `scripts/migrate.py` Step 6 and written to `vault/bases/`.
- File naming: `{folder_name}.base` — same name as the vault folder the base targets.
